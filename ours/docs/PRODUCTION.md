# Production path

What changes between this demo and a live Valio Aimo service. Every step preserves the same `/v1` REST and `/mcp` MCP contract.

1. **Identity and auth (`aimo/api.py`, `aimo/mandates.py`).** Auth is a single seam today: static `X-Agent-Key` bindings (`AIMO_AGENT_KEYS`, or `AIMO_AGENT_KEY` for MCP stdio) and one `X-Admin-Key` (`AIMO_ADMIN_KEY`). Production replaces static agent keys with OAuth 2.0 client credentials or mTLS bound to `(customer, agent_id)`, and replaces `X-Admin-Key` + `ApprovalDecision.by` with customer SSO/OIDC so the approver's identity comes from a verified human token rather than a request field.
2. **Signing keys (`aimo/keys.py`, `aimo/quotes.py`, `aimo/audit.py`).** Key rotation (`python -m aimo.keys rotate`) and multi-key JWKS (`retired-<kid>.json`, keeping pre-rotation quotes and audit checkpoints verifiable) are already implemented; see [STANDARDS](STANDARDS.md). Production moves Ed25519 private keys from `0600` files in `AIMO_KEY_DIR` to cloud KMS or an HSM and rotates on an automated schedule.
3. **ERP order adapter (`aimo/orders.py`).** Because the challenge API has no order placement endpoint (see [ASSUMPTIONS](ASSUMPTIONS.md)), `orders._confirm` currently records a simulated `MOCK-...` confirmation immediately after `placed`. Production swaps `_confirm` for an asynchronous Valio ERP/SAP order adapter: orders remain `placed` until the ERP confirmation callback arrives, using `quote_id` (already enforced as a `UNIQUE` `idem` column) as the idempotency key. Real ERP inventory shortfall events call `orders.react_stockout` in place of `/v1/admin/simulate`.
4. **Storage and audit anchoring (`aimo/db.py`, `aimo/audit.py`).** All database connections go through `aimo/db.py` (`AIMO_DB`), isolating the move from SQLite to PostgreSQL to the connection seam and schema migrations. `aimo/audit.py` already signs EdDSA head checkpoints (`GET /v1/audit` `checkpoint`, verified via `python -m aimo.audit verify-checkpoint`); production anchors those checkpoints periodically to an external transparency log or WORM object store.
5. **Upstream resilience and rate limiting (`aimo/valio.py`).** The client already batches up to `1,000` product IDs per request, retries `429` and `5xx` with `Retry-After` backoff, caches per `(endpoint, customer, date)`, falls back to stale cache on outage, and returns `503 UPSTREAM_UNAVAILABLE` instead of `500`. Production moves this cache to Redis with short TTLs aligned to price and stock SLAs and enforces per-agent and per-customer rate limits at the gateway edge.
6. **Observability.** Emit structured JSON logs, metrics, and OpenTelemetry traces keyed by `customer`, `agent_id`, `quote_id`, and `order_id`. Alert on `order.blocked` spikes, `pending_approval` orders approaching `closingTime` (`approvals.expire_stale`), and `UPSTREAM_UNAVAILABLE` error rates.
7. **Phased rollout.** Start read-only (`search_products`, `get_product`, `parse_request`, `get_offers`), then enable signed quotes (`request_quote`), then enable `place_order` with `substitutions="ask"` and conservative `per_order_eur` limits so every early order routes through human approval. Raise `per_order_eur` and `per_week_eur` per customer only after reviewing their hash-chained audit trail; see [TRUST](TRUST.md).
