# Judge Q&A: 23 hard questions

Short answers for the presenter, each with the file that backs it. Facts re-checked against main (`62e8384` / `f3c5996` / `2fe8975` / `4ccc1fb`) and `fr8/valio` on Sun 15 Nov unless marked otherwise. If a judge pushes past an answer, say what is demo-only and point at the production path; never round a number up.

## Permissions and control

**1. Can the agent approve its own order?**
No. MCP has no approval tool (13 tools, none decide). Over REST, any decision request carrying `X-Agent-Id` gets 403 `agent_cannot_approve`, even when it names the real approver with the correct quote hash, and the attempt is audited as `approval.refused`. We show this live: `docs/pitch/permissions_attack.py`. Code: `decide()` in `aimo/gateway/app.py`; tests: `tests/test_human_auth.py`.

**2. Then what stops the agent from just dropping the `X-Agent-Id` header and calling the decision endpoint?**
It then needs the human credential: a signed per-approver session (`X-Approver-Session`) or that approver's 12-character passphrase (`X-Approver-Pin`). No route or tool ever returns either; without one the answer is 401 and the attempt is audited. Five wrong guesses from one client for an approver lock that `(approver_id, client)` pair for 5 minutes (429 `approver_locked`), with a per-approver backstop of 30 per 10 minutes across all clients so attacking one approver never locks out other approvers or active sessions. `aimo/gateway/human_auth.py`, docs/TRUST.md "Human-only approvals".

**3. How are approver credentials isolated per person in the demo vs production?**
Each directory approver gets a distinct 12-character passphrase generated into `data/keys/approver_pins.json` (mode `0600`, overridable via `AIMO_APPROVER_PINS`, with `data/keys/approver_pin` synced to Anna's passphrase for local CLI scripts and `AIMO_APPROVER_PIN` kept only as an optional single-credential test override). One approver's passphrase cannot sign in or decide as another approver (Anna's cannot act as Mikko: 401, and it counts toward the lockout), a sign-in returns an 8-hour `X-Approver-Session` HMAC-bound to that person and their credential, and a session trying to decide as someone else gets 403 `approver_mismatch`. Production replaces local passphrases with the customer's own SSO (OIDC). `aimo/gateway/human_auth.py`, docs/TRUST.md, docs/ASSUMPTIONS.md.

**4. How do you know which agent is calling?**
In the demo, identity is two headers (`X-Customer-Id`, `X-Agent-Id`) checked against the known-customer directory and mandate (`aimo/gateway/auth.py`): an unknown customer gets 403 `unknown_customer` across `/v1`, catalog search, MCP and `/v1/agent/runs`, an unregistered agent gets 403 `scope_missing`, and quotes and orders refuse to run without identity. Unless `X-Agent-Key` is configured per customer, the demo headers are not cryptographically authenticated, so a caller that knows a registered pair can claim it. That is the biggest demo-only shortcut. Production: OAuth 2.1 client credentials per the MCP authorization spec, with spend limits as RFC 9396 `authorization_details`. docs/ASSUMPTIONS.md (A8), README "Production next steps".

**5. What if the agent lies, for example calls a substitute "preferred" to avoid approval?**
The gateway recomputes each line's substitution tier and flags itself and the policy re-verifies them; the agent's claims are ignored. A substitute sent as "preferred" comes back as "outside preference" and needs approval. The constraints of the parsed need are also locked once the agent calls `plan_need` or `create_quote`. `aimo/gateway/service.py` (`make_quote`), `aimo/buyer/agent.py` docstring.

**6. Who decides what is automatic and what needs a human?**
The customer, in a versioned YAML policy (`aimo/trust/policies/*.yaml`): spend limits, weekly budget, category scope, substitution tiers, allergen hard blocks, cut-off checks, drift, injection screening. Each rule returns a plain-language reason and the strictest outcome wins (reject > needs approval > auto). The €500 / €5,000 thresholds are illustrative and not validated with Valio. docs/ASSUMPTIONS.md.

**7. What exactly does the approver approve, and what if the price changes afterwards?**
The exact signed quote: Ed25519 JWS over canonical JSON, with a 15-minute price lock. Inside the lock, the quoted unit price holds; a decision with a different hash returns 409 `quote_hash_mismatch`. If the 15-minute lock expires while waiting and prices have moved, or if stock drops below the quoted quantity (`partial_stock`) or a cut-off passes before the human decides, `POST /v1/approvals/{id}/decision` returns 409 `requote_needed` with an old-vs-new diff (`detail.changes`), a replacement signed quote and a new pending order, recording `order.requoted` in the signed audit chain (never a silently partial order). In `/ui`, an expired lock shows "Price lock expired: re-price and review" and opens the old-vs-new diff card for one-click approval of the new `quote_hash`. So an approval can never be reused for a different price, quantity or product. Runnable beat: `uv run python docs/pitch/requote_beat.py --base http://localhost:8000`. `aimo/gateway/service.py`, `aimo/trust/`, docs/TRUST.md, docs/DEMO.md.

## Audit and evidence

**8. Your audit log is signed with your own key. Couldn't you rewrite the whole chain?**
Whoever holds the signing key could re-sign a rewritten chain, yes. The chain stops silent edits by anyone else (our tamper demo: one changed summary turns verify red at that event), and the evidence pack lets an auditor verify offline with the public JWKS. Production: the key in a KMS/HSM, events in WORM storage, and chain heads anchored externally (for example sent to the customer with each order response), so even the operator cannot rewrite history unnoticed. docs/ARCHITECTURE.md §5, README "Production next steps".

**9. How do we know your numbers are real?**
Every number is in docs/NUMBERS.md with the command that produces it and who re-ran it when, cross-checked by `tests/test_numbers_reproducibility.py` and `tests/test_docs_submission_hygiene.py` (1,150+ passed keyless offline in `fr8/valio`, 371 passed keyed / 270 passed keyless on standalone `main` `4ccc1fb` / `2fe8975` and 362 / 261 on `d4b0b41`, 0 failures without keys; 8/8 scenarios in replay; 44/44 conformance). The montage cost numbers ($0.0822 before the token trim, $0.0339 after the Saturday trim, and $0.0352 per order on the Sunday final-code re-record) recompute offline from the sanitized Gemini ledgers committed in docs/evidence/ (`uv run python docs/evidence/montage_stats.py`), and the final-code wind tunnel (0 policy and 0 allergen violations, 80 of 80 injection payloads blocked) re-scores offline from `docs/evidence/windtunnel/README.md`. Numbers we have not measured (gold-set accuracy, photo-intake accuracy) are listed as not claimed.

## Data and confidentiality

**10. What data goes to Gemini, and what about a real customer's confidential prices?**
The buyer agent sends the request text and compacted tool results (product names, prices, stock) to Gemini; trust and catalog calls send product text. The ledger stores token counts and latency only, never prompts or keys (`aimo/gemini.py`). All data here is the challenge's synthetic catalog and invented customers. For production we would run Gemini through Vertex AI in an EU region under enterprise terms (no training on customer data). The gateway itself never needs the model: any agent, including one the customer hosts, can use the same MCP tools. docs/DECISIONS.md, docs/ASSUMPTIONS.md.

**11. Can one customer's agent see another customer's orders or approvers?**
An agent's approval inbox is scoped to its own customer (asking for another returns 403 `customer_mismatch`), and `/v1/customers` shows agents approver names and roles but never their ids or emails. Given the header-only identity in Q4, this isolation becomes real once OAuth tokens replace the headers. `aimo/gateway/app.py` (`approvals`), docs/TRUST.md.

**12. What about prompt injection hidden in supplier product text?**
Two layers, and we report both honestly. The regex screen, which the shipped gateway runs by default, raises 0 false positives on 34,159 real supplier texts (`0 of 34,159`) and catches 44.4% of our separate 36-payload evaluation set (`windtunnel/screen_eval.py`). The Gemini classifier (`gemini-3.1-flash-lite`) reaches 94.4% recall on that 36-payload set (0 of 60 false positives on supplier texts) but flags 42 of 60 normal buyer requests, so it is opt-in (`AIMO_SCREEN_GEMINI=1`, off by default). Every `PlanLine` and `Candidate` surfaces `injection_screen` during planning (`aimo/catalog/screening_bridge.py`), the policy and planner also screen the buyer request (`need.raw_text` and `need.product_query`), the buyer harness redacts flagged text before the model sees it, and a flagged order only sends the order to a human; the real protection is that the policy, the signed quote and the human approval do not depend on the screen catching everything. In the Sunday live montage, 6 planted texts were flagged and redacted on the regex screen (4 in the earlier Saturday run) and the order quantity stayed at 300; in the final-code wind tunnel, the regex screen flagged 80 of 80 of the scenarios' injection payloads (40 supplier text + 40 buyer request / `product_query`, vs 0 of 80 for a naive agent) with 1 false positive in 560 clean requests (those scenario payloads are easier than the 36-payload evaluation set). `aimo/trust/screening.py`, docs/windtunnel-results.md, `docs/evidence/windtunnel/README.md`.

## Robustness and failure modes

**13. What happens when the Valio API is slow, rate-limited or down?**
The client batches up to 1,000 ids, caches for 5 minutes and retries with backoff; after that, if live upstream fails (or when no `AIMO_API_KEY` is configured in S1 auto-replay, or `AIMO_REPLAY=1`), `aimo/backend/replay.py` serves recorded responses from the bundled snapshot `tests/fixtures/snapshot/replay/` (669 products and catalog subset across 5 delivery dates `2026-11-16`..`2026-11-20`) marked `served_from: replay` (the UI shows a `REPLAY` pill; disable fallback with `AIMO_REPLAY_FALLBACK=0` for a strict 503 with `Retry-After`, never a guessed price). That lets a fresh keyless clone pass `scenarios.run_all` 8/8 (88 checks), conformance (44/44) and `make accept` offline. Unavailable quote lines are refused with per-line reasons (409) so the agent re-plans; if stock drops below the quoted quantity while the order waits for a human, approval returns 409 `requote_needed` (reason `partial_stock`) with a fresh quote, never a silently partial order. Every exception can be reproduced per request with `X-Aimo-Faults` (and simulated clock `X-Aimo-Now`), which are operator-only: on any request carrying agent identity over REST or MCP they are ignored unless the gateway was started with `AIMO_DEMO_FAULTS=1` (and never honoured with `AIMO_ENV=production`). Bad input never crashes the gateway: a fuzz test sends about 2,600 malformed requests to every `/v1` route with 0 server errors, and agent runs that cannot reach the gateway fail within seconds instead of hanging (`tests/test_fuzz.py`, `tests/test_overrides.py`, `aimo/buyer/runs.py`). `aimo/backend/client.py`, `aimo/backend/replay.py`, docs/reports/replay.md, docs/interfaces.md.

**14. What if Gemini fails or hallucinates?**
Need parsing has a deterministic cross-check: relative dates are re-resolved in Helsinki time, and the regex detector can add a claim or allergen but never remove one. Gemini allergen readings can only block a product, never clear it, and unknown allergens are never "safe". The harness allows at most one `place_order` per run and stops after a rejection. The Gemini wrapper retries 429/5xx; if Gemini stays down or no API key is configured, need parsing falls back to the keyless deterministic regex parser and `uv run aimo demo` runs a clearly labelled scripted buyer fallback through the same real gateway, policy, signing and approval harness (pairing with S1 auto-replay in `tests/fixtures/snapshot/replay/` when keyless so the full demo and `scenarios.run_all` 8/8 run with zero keys). Whatever the model does, an order needs a valid signed quote and, above the customer's limits, a human. `aimo/buyer/need.py`, `aimo/buyer/mock_model.py`, `aimo/catalog/gemini_allergens.py`.

**15. Your escalation precision is only 68%-70%. Isn't the gateway just asking a human about everything?**
It errs towards asking, on purpose. On 640 Gemini-written scenarios: recall 99.7% and 0 policy and 0 allergen violations, against 372 and 193 for a naive agent. Precision went from 54.0% to 68.2% after the S3 policy update and 69.5% on the final policy: the gateway verifies substitution tiers against the catalog itself, treats a first purchase as a purchase rather than a swap, auto-approves verified alternatives under a small amount (hotel: €50), lets a pack swap the customer listed pass on its own under the spend limit, and applies remembered "always allow this swap" decisions. Our 90% target is not met; see Q21 for the full breakdown of what is left. docs/windtunnel-results.md, `docs/evidence/windtunnel/README.md`, docs/reports/need.md.

**16. What about splitting one big order into many small ones to stay under the limit?**
The `split_order` rule adds up orders of the same thing (same product, standing-order product, category or request phrase) placed without a human in the last 7 days (7-day rolling window): once they pass the auto limit, the next one needs approval (3 × €399.96 of milk at the hotel: auto, then needs approval on the second). Quantity drift (`quantity_drift`) also counts the last 7 days, the weekly budget sums all orders, and a unit price more than 15% above the last price paid needs approval (`price_jump`). After these changes the wind tunnel shows 0 policy violations, including the `split_order` family. `aimo/trust/policy.py`, docs/reports/need.md.

## Openness and production

**17. Why MCP and not just a REST API?**
Both, from one service layer: MCP because the agents buyers actually use (Claude, Gemini CLI, Cursor, agent frameworks) discover and call MCP tools with no integration code, and OpenAPI 3.1 for ERPs and classic integrations. Discovery is one manifest (`/.well-known/otap.json`). We showed it is not tied to us: a second, synthetic wholesaler passes the same 44-check conformance suite (44/44), and the same Gemini agent bought from it with only the URL changed. docs/OPENNESS.md, `conformance/`.

**18. Is the order real? Valio's API has no order endpoint.**
Prices and availability are live from the challenge's mock API. Orders go to our own mock order service behind the same `BackendClient` interface a SAP adapter would implement, and the answer is a Peppol-style order response (AP/CA/RE), exportable as Peppol BIS T116 UBL XML (checked against the PEPPOL-T116 rules by default and opt-in against the UBL 2.3 XSD via `AIMO_UBL_XSD`; full schematron not run). README "Openness", docs/peppol/.

**19. What is the path to production?**
Read-only first, then quotes, then orders with every order human-approved, then autonomy inside limits relaxed one rule at a time from audit evidence (allergen rules never relax for schools and hospitals). In parallel: SAP adapter for contract prices and real available-to-promise, GS1 Synkka as the allergen truth source, OAuth 2.1 and customer SSO, KMS keys, WORM audit, Peppol through Valio's access point. Valio legal must confirm whether a signed quote is a binding offer. README "Production next steps", docs/ARCHITECTURE.md §5.

## Gemini

**20. Why Gemini, and what does it cost?**
The catalog is mostly Finnish and Swedish; Gemini reads it directly, and gemini-embedding-2 puts "laktoositon maito" next to "lactose-free milk" in the same API. Thinking levels let us spend reasoning only on the substitution decision: routine steps run on gemini-3.8-flash LOW, and only the quote-decision turn escalates to gemini-4-hydrogen HIGH (5 of 34 steps, 15%, in the Sunday final-code montage; 6 of 31 steps, 19%, in the Saturday run). We measured that choice: hydrogen HIGH was 100% accurate on both parse and substitution tasks with p95 under 7.2 s, while flash HIGH came close (100% parse, 97.9% substitution) but hit a 69.5 s p95 on parsing. Cost: $0.0352 of Gemini per placed order on the final code ($0.0339 after the Saturday token trim, down 57%-59% from $0.0822 before the trim), with 38% of input served from the implicit cache on Sunday (31% on Saturday). docs/GEMINI.md, docs/evidence/.

## Final-round hardening

**21. Why does it ask a human this often (68.2% / 69.5% precision)?**
Because it is built to stop when unsure. In the final-code wind tunnel (640 Gemini-written scenarios) it let through 0 policy and 0 allergen violations and missed only 1 required escalation (99.7% recall), escalating 331 times when it had to and 145 times when auto-approval would also have been acceptable (69.5% precision with the hotel's listed pack swap allowed under the spend limit, up from 68.2% after S3 and 54.0% before; our 90% target is not met). Of the 145 extra escalations, about 37 are deliberate stops (21 detected injection attempts, 16 price jumps over 15%). About 43 are a real improvement still to make: the planner chose a non-usual product where the usual one would do. Most of the rest is the school's and hospital's own rule that any substitution needs the kitchen manager or dietitian. Each human "always allow this swap" teaches the gateway that swap (`aimo/trust/learned.py`), so the same question is not asked again, a pack swap the customer listed passes alone under the spend limit, and small verified alternatives under €50 go through alone. `docs/evidence/windtunnel/README.md`, `docs/windtunnel-results.json`, `aimo/trust/learned.py`.

**22. Can an agent move the clock or fake stock?**
No. The demo clock (`X-Aimo-Now`) and fault injection (`X-Aimo-Faults`: stock-outs, price shocks, injected text) are operator tools: on any request carrying agent identity, over REST or MCP, the gateway ignores them unless the operator started it with `AIMO_DEMO_FAULTS=1`, and never with `AIMO_ENV=production`. So an agent cannot backdate "now" past a cut-off or invent stock. A judge panel re-score on Sunday morning found one more door: the `faults` field in the body of `POST /v1/agent/runs` bypassed that check and produced a signed €10.10 quote for 1,000 L. It is closed (`4ccc1fb` / `2fe8975`): body `faults` and caller-chosen `inproc`/`fake` test transports on `POST /v1/agent/runs` are ignored unless the operator enabled `AIMO_DEMO_FAULTS=1` (and never in production), and starting, answering or listing `/v1/agent/runs` requires a signed-in human (`X-Approver-Session` or `X-Approver-Pin`, 401 otherwise; in `/ui`, clicking **Run agent** opens the sign-in panel first); `tests/test_run_api_guard.py`. Prices and stock come from the backend; the quote is signed; and if stock drops while the order waits for approval, the approval returns 409 `requote_needed` (`partial_stock`) instead of a silently partial order. `tests/test_overrides.py`, `tests/test_gateway.py::test_partial_stock_at_approval_requotes_instead_of_silently_less`, docs/TRUST.md.

**23. What happens if Gemini runs out of quota during the demo?**
It happened for real at Sun 15 Nov 05:00: the shared key hit `gemini-3.8-flash`'s daily limit and agent runs failed with 429. Now `aimo.gemini.generate` falls back at once on daily-quota exhaustion (or repeated rate-limits) to the next model in `GEMINI_FALLBACK_MODELS` (default `gemini-3.5-flash`, then `gemini-4-hydrogen`), skips the exhausted model for 30 minutes, and records the model that actually answered in the agent steps and usage ledger (`meta.fallback_from`); the hero run then placed its order in 29 s on `gemini-3.5-flash`. If no model answers, the run stops cleanly with an error and nothing is ordered; the keyless scripted model (`uv run aimo demo` without `GEMINI_API_KEY`) and `qa_milk_flow.py` still run the whole flow end to end. Our committed montage numbers were measured on `gemini-3.8-flash`. `aimo/gemini.py`, `tests/test_gemini_fallback.py`.
